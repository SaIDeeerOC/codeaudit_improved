# ЗАПУСК.md — как запустить конвейер (инструкция для тех, кто делает это впервые)

## Что это такое в двух словах

`pipeline.py` — это проверерка качества кода. Вы даёте ей папку с Git-репозиторием,
она просматривает код и историю коммитов и пишет отчёт: где ошибки, уязвимости,
несовместимости со стилем, случайно закоммиченные пароли/ключи и плохие коммиты.
В конце ставит оценку от 0 до 100 и решает: «quality gate пройден» или «не пройден».

## Совсем с нуля: что делать (минимум действий)

«Устанавливать» файлы проекта не нужно: папка просто лежит где угодно (хоть на
Рабочем столе), и всё запускается прямо из неё. Установить нужно только две
сторонние программы из раздела 0 — Python и Git. Из всех файлов проекта тебе
лично нужно тронуть максимум два:

Главный способ — меню: двойной клик по `run.bat` (Windows) или команда
`python3 run.py` (Linux/macOS). Меню умеет всё то же самое и подсказывает,
что делать: пункт 1 — демо, пункт 2 — проверка своего репозитория, пункт 3 —
пороги строгости, пункт 4 — справка. Готовый отчёт меню предложит открыть
в браузере само.

Старые способы тоже работают (оставлены для совместимости):

1. **Проверить, что всё работает.** Двойной клик по `run_demo.bat` (Windows).
   Откроется чёрное окно, оно само создаст учебный репозиторий с дефектами,
   проверит его и напишет, где отчёт. Открой `demo_out/report.html` в браузере.
2. **Проверить свой репозиторий.** Перетащи папку своего проекта (ту, внутри
   которой есть `.git`) на иконку `check_repo.bat` — отчёт появится в
   `report_myrepo/report.html`. Командный способ — в разделе 2 ниже.

## Зачем нужен каждый файл

| Файл | Что это | Что с ним делать тебе |
|---|---|---|
| `run.py`, `run.bat` | Единое меню: демо, свой репозиторий, пороги, справка | Главный способ: двойной клик по `run.bat` (Windows) или `python3 run.py` |
| `run_demo.bat` | Старый способ: демо одним двойным кликом (Windows) | Работает, но меню удобнее |
| `check_repo.bat` | Старый способ: проверка своего репозитория | Перетащить на него папку репозитория |
| `pipeline.py` | Сам конвейер, главный файл | Ничего — запускается сам |
| `codeaudit/` | Модули сканеров, Git-аудита, кэша, настроек и отчётов | Не менять для обычного запуска |
| `run_demo.py`, `run_demo.sh` | Тот же демо-запуск через Python / под Linux, macOS (старый способ) | Ничего |
| `config.toml` | Настройки: пороги оценки, правила | По желанию |
| `semgrep-rules/local.yml` | Правила поиска уязвимостей | Ничего |
| `demo_report.html` | Пример готового отчёта | Открыть в браузере, посмотреть, как выглядит результат |
| `ЗАПУСК.md` | Эта инструкция | Читать |
| `README.md` | Описание проекта (для отчёта и преподавателю) | Читать |
| `.gitignore` | Служебный файл для git | Ничего |
| `pre-push-hook.sh`, `.gitea-ci.yml`, `Dockerfile` | Автопроверка перед push, CI, Docker | Не нужно (по желанию) |
| `bench/bench.py`, `bench/results.json`, `bench/results.md` | Замер качества конвейера (метрики из README) | Не нужно |

Примечание: надписи внутри `run_demo.bat` и `check_repo.bat` сделаны на английском —
специально, чтобы bat-файлы не зависели от кодировки консоли Windows (кириллица
и скобки внутри bat ломают его разбор). Меню `run.py` печатается по-русски;
сам конвейер и отчёты тоже по-русски.

## 0. Что должно быть установлено

| Что | Где взять | Как проверить |
|---|---|---|
| Python 3.11 или новее | https://www.python.org/downloads/ (на Windows при установке отметьте «Add to PATH») | `python3 --version` (Windows: `py --version`) |
| Git | https://git-scm.com/downloads | `git --version` |

Больше ничего не нужно: pip-пакеты не требуются, интернет не используется.

## 1. Проверка, что всё работает (самый простой запуск)

Самый простой путь — меню: двойной клик по `run.bat` (Windows) или в терминале
`python3 run.py`, затем пункт `1`. Демо можно запустить и напрямую:

```bash
# Linux / macOS / Git Bash на Windows:
python3 run_demo.py

# Windows (обычный cmd или двойной клик по файлу):
run_demo.bat
```

Скрипт сам создаст во временном каталоге учебный репозиторий с дефектами
(пароль в коде, `eval()`, SQL-инъекция, коммит «wip» и др.), прогонит конвейер
и скажет, где отчёт. Ожидаемый результат: строка вида
`Оценка …/100, high+critical=…, gate=FAILED` и код возврата 1 — это **нормально**:
в демо-репозитории дефекты специально заложены, конвейер должен был их найти и отказать.
Отчёты появятся в папке `demo_out/` — откройте `demo_out/report.html` в браузере.

## 2. Проверка своего реального репозитория

Самый простой способ: меню — `run.bat` → пункт `2`: вставь путь к папке
репозитория, отчёт появится в `report_myrepo/`, и меню предложит открыть его
в браузере. Ленивый вариант — перетащить папку на иконку `run.bat`: то же
самое без лишних вопросов. Вручную то же самое:

```bash
python3 pipeline.py /путь/к/репозиторию --out report --config config.toml
```

- Вместо `/путь/к/репозиторию` — папка вашего проекта (с подпапкой `.git`).
  На Windows путь пишется так: `pipeline.py C:\Users\имя\мои-проекты\repo`.
- Если репозиторий пока есть только на GitHub — сначала склонируй его на диск:
  `git clone https://github.com/логин/имя-репо.git` (ссылку взять на странице
  репозитория: зелёная кнопка Code → HTTPS; появится папка, внутри которой
  есть `.git`). Не используй кнопку Code → Download ZIP: в такой папке нет `.git`,
  и все проверки истории коммитов будут пропущены.
- После работы смотрим `report/report.md` (текст) или `report/report.html` (браузер).
- Код возврата: **0** — gate пройден, **1** — gate не пройден или скан неполный,
  **2** — ошибка запуска (например, каталог или конфигурация не найдены).
- Если этап сканирования завершился ошибкой, отчёт помечается как неполный и gate
  не будет пройден. Ошибка или неверное значение в `config.toml` останавливает запуск
  с кодом 2.
- Если в окне консоли всё «замерло» и ничего не печатается — сначала нажми
  Enter (или Esc) прямо в окне. Клик мышью по консоли Windows включает выделение
  текста и на время ставит вывод программы на паузу (режим QuickEdit) — конвейер
  при этом жив и продолжит с места остановки.
- Повторный прогон быстрее: неизменённые файлы берутся из кэша (`.scan_cache.json`
  в папке отчёта). Отключить кэш: добавить флаг `--no-cache` в командную строку.
- Каждый прогон дописывает строку в `history.jsonl` (там же, в папке отчёта),
  и в отчёте появляется раздел «Динамика проверок» — как менялись оценка и gate.
- Пороги (сколько high/critical допустимо, минимальная оценка) меняются в `config.toml`.

## 3. Автопроверка перед push (pre-push hook)

```bash
cp pre-push-hook.sh .git/hooks/pre-push && chmod +x .git/hooks/pre-push
```

После этого `git push` сначала прогонит конвейер: если gate не пройден, push
будет отклонён (отчёт в `/tmp/audit-report/`). На Windows hook запускается
из Git Bash, который ставится вместе с git.

## 4. Бенчмарк: воспроизведение метрик из README

```bash
python3 bench/bench.py --repos 30 --clean 6
```

Займёт около минуты. Скрипт создаст 36 репозиториев с заранее известными
дефектами, прогонит конвейер на каждом и обновит `bench/results.md`
(это та самая таблица TP/FP/FN/precision/recall/F1 из README).
Временные репозитории создаются в уникальной подпапке и удаляется только эта
подпапка. Параметр `--work` задаёт её родительскую папку; существующие данные
в ней не удаляются.

Запустить тесты проекта отдельно можно командой:

```bash
python3 -m unittest discover -s tests -v
```

## 5. Внешние инструменты (необязательно, но повышает качество)

Встроенные проверки работают всегда. Если установить открытые инструменты,
конвейер подхватит их **автоматически** при следующем запуске:

```bash
pip install ruff bandit semgrep          # Python-инструменты
# gitleaks и shellcheck ставятся из репозиториев ОС (apt install …)
```

Если инструмент не установлен, в отчёте будет строка
`инструмент: не установлен или не настроен - пропущен` — это не ошибка.

## 6. Docker (необязательно)

```bash
docker build -t codeaudit .
docker run --rm -v "$PWD":/repo -v "$PWD/report":/report codeaudit
# Windows PowerShell: -v ${PWD}:/repo -v ${PWD}/report:/report
```

## 7. CI на self-hosted Gitea / GitLab

Файл `.gitea-ci.yml` уже в проекте: конвейер запускается на каждый push и pull
request на раннере с меткой `self-hosted`. Важно: в checkout должно стоять
`fetch-depth: 0` — иначе аудит не увидит всю историю коммитов.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `Каталог не найден` (код 2) | Путь к репозиторию неверный; путь с пробелами берите в кавычки |
| Окно от .bat закрывается мгновенно, ничего не видно | Две частые причины: (1) bat запущен прямо внутри zip-архива — распакуйте архив целиком и запускайте из распакованной папки; (2) Python не найден — переустановите его с галочкой «Add to PATH». Чтобы увидеть текст ошибки: откройте папку с bat, наберите `cmd` в адресной строке проводника и запустите bat командой в открывшемся окне |
| `Предупреждение: для чтения config.toml нужен Python 3.11+` | Обновите Python или запускайте без `--config` (будут настройки по умолчанию) |
| Находок категории git нет, `no-history` | В папке нет `.git` или история пуста; проверьте, что указываете на корень репозитория |
| `py не найден` в Windows | Ставьте Python с галочкой «Add to PATH» и переоткройте терминал |
| Долго не запускается semgrep при первом прогоне | Он сканирует по локальным правилам без сети; если хочется совсем без него — удалите каталог `semgrep-rules` (конвейер пропустит стадию) |
