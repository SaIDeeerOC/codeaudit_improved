# Руководство по запуску CodeAudit

## Назначение

`pipeline.py` анализирует исходный код и историю коммитов указанного Git-репозитория.
Отчёт содержит обнаруженные ошибки, уязвимости, стилевые несоответствия, секреты и
замечания к истории Git. По результатам анализа рассчитывается оценка от 0 до 100 и
определяется, выполнены ли условия quality gate (критерия допуска).

## Первый запуск

Установка проекта не требуется. Для запуска необходимы Python 3.11 или новее и Git (см. раздел
«Системные требования»). Проект можно запускать из каталога, в который он распакован.

Основной способ запуска — интерактивное меню: выполните `run.bat` в Windows или
`python3 run.py` в Linux/macOS. Меню содержит следующие пункты:

- `1` — демонстрационный анализ;
- `2` — анализ выбранного репозитория;
- `3` — просмотр и изменение порогов;
- `4` — справочная информация;
- `5` — диагностика окружения.

Для каждого репозитория меню предлагает отдельный каталог отчётов; при необходимости
можно указать другой путь. После завершения анализа меню предложит открыть HTML-отчёт
в браузере.

Также доступны отдельные сценарии запуска:

1. **Демонстрационный анализ.** Запустите `run_demo.bat` в Windows. Скрипт создаст
   временный репозиторий с дефектами, выполнит анализ и укажет расположение отчёта.
   HTML-отчёт находится в `demo_out/report.html`.
2. **Анализ репозитория.** Передайте каталог проекта, содержащий `.git`, файлу
   `check_repo.bat` или `run.bat`. Меню предложит выбрать каталог для отчёта.
   Запуск из командной строки описан в разделе «Анализ репозитория».

| Что | Где взять | Как проверить |

## 1. Демонстрационный анализ

Демонстрационный анализ запускается через меню (`run.bat` в Windows или
`python3 run.py` в Linux/macOS, затем пункт `1`) либо напрямую:

```bash
# Linux / macOS / Git Bash на Windows:
python3 run_demo.py

# Windows (обычный cmd или двойной клик по файлу):
run_demo.bat
```

Скрипт создаёт во временном каталоге репозиторий с заранее внесёнными дефектами
(например, паролем в коде, вызовом `eval()`, SQL-инъекцией и коммитом «wip»), запускает
конвейер и выводит расположение отчёта. Ожидаемый результат — сообщение вида
`Оценка …/100, high+critical=…, gate=FAILED` и код возврата 1. Такой результат
предусмотрен: демонстрационный репозиторий содержит дефекты, поэтому quality gate
не должен быть пройден. Отчёты сохраняются в `demo_out/`; HTML-отчёт находится
в `demo_out/report.html`.

## 2. Анализ репозитория

Для запуска через меню выполните `run.bat` в Windows или `python3 run.py` в Linux/macOS,
выберите пункт `2` и укажите путь к репозиторию. Нажмите Enter, чтобы использовать
предложенный каталог в `reports/`, или укажите другой путь. Если каталог отчётов уже
содержит результаты, меню запросит подтверждение перед обновлением. После завершения
анализа можно открыть HTML-отчёт в браузере.

Каталог репозитория также можно перетащить на файл `run.bat`. Для запуска из командной
строки используйте:

```bash
python3 pipeline.py /путь/к/репозиторию --out report --config config.toml
```

- Укажите каталог проекта, содержащий `.git`. В Windows путь имеет вид:
  `C:\Users\имя\мои-проекты\repo`.
- Если репозиторий размещён только на GitHub, сначала клонируйте его:
  `git clone https://github.com/логин/имя-репо.git`. HTTPS-ссылку можно скопировать
  на странице репозитория через меню Code → HTTPS. Загрузка через Code → Download ZIP
  не включает каталог `.git`, поэтому аудит истории коммитов будет пропущен.
- После выполнения анализа отчёт доступен в `report/report.md` и `report/report.html`.
- Код возврата: **0** — gate пройден, **1** — gate не пройден или скан неполный,
  **2** — ошибка запуска (например, каталог или конфигурация не найдены).
- Если этап сканирования завершился ошибкой, отчёт помечается как неполный и gate
  не будет пройден. Ошибка или неверное значение в `config.toml` останавливает запуск
  с кодом 2.
- Если вывод в консоли приостановился, нажмите Enter или Esc. В Windows выделение
  текста мышью может активировать режим QuickEdit и временно приостановить вывод;
  после выхода из режима выполнение продолжится.
- При повторном запуске результаты для неизменённых файлов берутся из кэша
  (`.scan_cache.json` в каталоге отчёта). Для отключения кэша используйте параметр
  `--no-cache`.
- Каждый запуск добавляет запись в `history.jsonl` в каталоге отчётов. Отчёт содержит
  раздел «Динамика проверок» с историей оценок и результатов gate.
- Меню создаёт отдельный каталог отчётов для каждого репозитория в `reports/`.
  Повторный анализ того же репозитория обновляет отчёт и сохраняет историю; каталог
  можно задать вручную. HTML-отчёт поддерживает поиск и фильтрацию по критичности,
  категории и статусу, а также содержит рекомендации по распространённым находкам.
- В терминале отображаются этапный прогресс, продолжительность текущего этапа и число
  просмотренных файлов для крупных репозиториев.
- Пункт меню `5` выполняет диагностику версии Python, Git, конфигурации, прав записи
  и доступности необязательных внешних анализаторов.
- Пороговые значения (допустимое число находок high/critical и минимальная оценка)
  задаются в `config.toml`.

### Временные исключения для находок

Чтобы временно исключить подтверждённую находку из оценки и quality gate, добавьте
в корень анализируемого репозитория файл `.codeaudit-suppressions.toml`:

```toml
[[suppressions]]
rule = "dangerous-eval"
file = "src/example.py"
line = 12 # необязательное поле; без него исключаются все совпадения правила в файле
reason = "Подтверждённое использование в тестовом стенде"
expires = 2027-01-31
```

Для каждого исключения указываются точное имя правила, путь внутри репозитория, причина
и дата истечения. После истечения исключение перестаёт применяться, а находка снова
учитывается при расчёте оценки и quality gate. Исключённые находки сохраняются в HTML-,
Markdown- и JSON-отчётах вместе с причиной и сроком. Альтернативный файл задаётся
параметром `--suppressions путь`.

## 3. Проверка перед отправкой изменений в Git

```bash
cp pre-push-hook.sh .git/hooks/pre-push && chmod +x .git/hooks/pre-push
```

После установки hook перед выполнением `git push` запускается конвейер. Если quality gate
не пройден, отправка изменений отменяется; отчёт сохраняется в `/tmp/audit-report/`.
В Windows hook выполняется через Git Bash, устанавливаемый вместе с Git.

## 4. Воспроизведение результатов бенчмарка

```bash
python3 bench/bench.py --repos 30 --clean 6
```

Выполнение занимает около минуты. Скрипт создаёт 36 репозиториев с размеченными
дефектами, запускает анализ и обновляет `bench/results.md` с метриками TP, FP, FN,
precision, recall и F1. Временные репозитории создаются в уникальном дочернем каталоге;
по завершении удаляется только созданный скриптом каталог. Параметр `--work` задаёт
его родительский каталог, содержимое которого сохраняется.

Для запуска тестов проекта выполните:

```bash
python3 -m unittest discover -s tests -v
```

Набор включает проверки на безопасных контрольных примерах. Интеграционные тесты Ruff,
Bandit, Semgrep, Gitleaks и ShellCheck запускаются при наличии соответствующего
инструмента; в противном случае тесты помечаются как пропущенные. В CI тесты выполняются
до анализа самого репозитория.

## 5. Дополнительные анализаторы

Встроенные проверки доступны без дополнительных компонентов. При установке внешних
инструментов конвейер обнаруживает их автоматически:

```bash
pip install ruff bandit semgrep          # Python-инструменты
# gitleaks и shellcheck ставятся из репозиториев ОС (apt install …)
```

Если инструмент отсутствует, соответствующая стадия будет пропущена с сообщением
`инструмент: не установлен или не настроен - пропущен`.

## 6. Запуск в Docker

```bash
docker build -t codeaudit .
docker run --rm -v "$PWD":/repo -v "$PWD/report":/report codeaudit
# Windows PowerShell: -v ${PWD}:/repo -v ${PWD}/report:/report
```

## 7. Интеграция с CI

Файл `.gitea-ci.yml` содержит конфигурацию запуска конвейера при push и pull request
на runner с меткой `self-hosted`. Для анализа полной истории Git параметр checkout
`fetch-depth` должен быть равен `0`.

## Диагностика распространённых проблем

| Симптом | Причина и решение |
|---|---|
| `Каталог не найден` (код 2) | Проверьте путь к репозиторию. Пути, содержащие пробелы, заключайте в кавычки. |
| Окно `.bat` закрывается сразу после запуска | Возможные причины: файл запущен непосредственно из ZIP-архива (распакуйте архив) или Python отсутствует в `PATH` (установите Python с параметром «Add to PATH»). Для просмотра сообщения об ошибке откройте каталог с `.bat`, введите `cmd` в адресной строке Проводника и запустите файл из открывшегося окна. |
| `Предупреждение: для чтения config.toml нужен Python 3.11+` | Установите Python 3.11 или новее либо запустите конвейер без `--config`, чтобы использовать настройки по умолчанию. |
| Отсутствуют находки категории Git, указан `no-history` | Проверьте наличие `.git` и укажите корень репозитория. История также может быть пустой. |
| `py не найден` в Windows | Установите Python с параметром «Add to PATH» и перезапустите терминал. |
| Semgrep долго запускается при первом анализе | Semgrep выполняет сканирование по локальным правилам без доступа к сети. Чтобы пропустить эту стадию, удалите каталог `semgrep-rules`. |
